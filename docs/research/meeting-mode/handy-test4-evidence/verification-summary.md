Le packager confirme les empreintes JNI épinglées ; l’APK principal et l’APK androidTest définitif passent le contrôle d’alignement 16 Kio et la vérification de signature v2. Le SHA-256 de l’APK principal est `0ad1d9dd283a2d33edf6e42b19db6d1cfcc0e3a332c234bd1dec8ab1d74d0732` ; celui de l’APK androidTest définitif est `d6db33d57fccbc6313eb0b045398fef5d0df6f4cab5621f07e8a4a55320951c6`.

Les suites Python sont vertes : outillage natif, 16 tests ; préparation et vérification APK, 11 tests. Les suites JVM finales passent en variante normale et en variante prototype ; chacune exécute 1 099 cas, sans échec, erreur ou test ignoré. Le premier run normal avait révélé une attente UI obsolète sur la taille du catalogue (849 Mo) ; après correction du test pour calculer la valeur depuis le catalogue, le rerun complet est vert. Les résultats XML de 135 suites pour chaque variante sont conservés dans les dossiers `jvm-normal-final-post-ui-xml` et `jvm-prototype-final-post-ui-xml`.

Sur l’AVD API 36 ARM64, la fixture française synthétique publique de 12,78 s donne le même texte complet dans les trois phases Handy seul / Handy avec diarisation / Handy seul. Les durées de sortie finale sont respectivement 19,737 s, 20,549 s et 16,494 s ; cette petite série montre aussi une variation entre passes et ne constitue pas un seuil de performance. Le test intégré via le moteur publie du texte avant `finish`, conserve le rendu final exact et ferme ses ressources.

Le profil soutenu de 63,9 s a échoué : avec Handy et la diarisation simultanés, la file de diarisation n’a pas été drainée dans le délai borné de 120 s. Le retard de file a augmenté au fil de l’audio ; ce profil reste un échec documenté et n’est pas présenté comme un débit soutenu validé.

Ces résultats proviennent de l’émulateur et de fixtures publiques. Ils ne valident ni la latence, ni la mémoire, ni la qualité de transcription sur le Poco F7. Aucun APK, modèle, binaire `.so` ou audio n’est copié dans ce dossier de preuves.
