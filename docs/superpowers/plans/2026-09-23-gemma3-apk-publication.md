# Publication du pilote Gemma 3 dans GitHub Actions

Lot complexe, deux revues Astra avant commit/push. L'utilisateur a demandé une nouvelle version de test via GitHub Actions. Le chantier Android est décrit dans `2026-09-23-gemma3-apk-integration.md` ; les modifications du runtime et de Gradle sont gérées par les autres agents. Ce lot n'autorise aucun nouveau calcul d'entraînement ni aucune publication des archives d'entrées.

Luna 6 Max possède `.github/workflows/build.yml`, `scripts/prepare_ci_apk.py`, leurs tests de contrat, une notice spécifique G3 et la notice de test Markdown. Préserver G4/GPU/normal. Ajouter l'entrée `gemma3_repair_pilot` et le marqueur `[gemma3-latency-test]`, un chemin de build `-Pgemma3RepairPilot=true`, l'artefact `dictai-gemma3-test` et le fichier `dictai-gemma3-test.apk`. Refuser explicitement une sélection simultanée G3/G4 avant la compilation. Les commits `[gemma3-training-only]` ne déclenchent toujours pas d'APK.

Le build G3 doit inclure les deux JNI CPU, ne contenir aucun poids, passer les tests JVM et produire également les tests instrumentés, puis passer signature et alignements ZIP/ELF 16 Ko. Le script de packaging exige une notice G3 distincte ; ne pas supprimer les notices historiques. Ajouter les tests RED/GREEN de routage/packaging, y compris sélections conflictuelles et mauvaise variante. Si une assertion textuelle historique sur Gradle devient périmée, la mettre à jour en préservant le contrat version G4=39, autres variantes=35, G3=40, et non en supprimant le contrôle.

Ajouter une publication prerelease séparée, limitée à ce marqueur ou à une demande manuelle G3 avec `publish_prerelease`. Tag `gemma3-test-$GITHUB_RUN_ID`, titre « DictAI 0.9.11 — essai Gemma 3 à attente courte », SHA256SUMS. L'APK conserve `com.uhama.whisperpin` et la clé debug du dépôt. Pas de publication automatique d'une variante différente. Ne pas exécuter d'Action avant décision explicite du principal sur les poids et deux revues du lot achevé.

Pour la préparation, les notes décrivent la référence V3 existante (291545280 octets, SHA `6c4b7b6654c9638287c31e50fd0bf849f33a2ff2dd93bee685bdd9632f20ecf5`, release `gemma270-v3-model`). Elles doivent dire explicitement que les poids V3 sont inchangés si ce choix est confirmé ; l'amélioration alors testée porte sur le retour au petit modèle, la limite d'attente et les gardes. Le résultat MLP sera intégré à la notice après arbitrage : aucun candidat rejeté ne sera annoncé comme une amélioration du modèle.

Expliquer simplement le test : installer comme mise à jour, ouvrir Mise en forme, choisir Local puis Texte corrigé et installer le modèle G3 d'environ 292 Mo ; ne pas désinstaller l'application ni effacer ses données. La limite de 3 secondes concerne l'attente de correction après finalisation ASR et non le temps total arrêt→insertion. Le texte reconnu reste disponible si le calcul expire ou si la sortie est refusée. Le pilote ne qualifie pas listes/mails ni correction progressive par Gemma ; l'ASR direct et l'édition de l'overlay restent disponibles. Les chiffres du téléphone restent à mesurer.

Après publication autorisée : suivre l'Action jusqu'au résultat, récupérer l'artefact neuf, comparer SHA/taille au téléchargement release, vérifier applicationId, versionCode 40, versionName, ARM64, minSdk 30, certificat égal à la dernière livraison 0.9.10 et alignements. Vérifier les notices et l'absence de poids. Signaler l'absence d'appareil connecté ; ne pas prétendre avoir testé l'installation Poco/Pad ou la latence réelle. Remettre le lien direct de l'APK seulement après ces contrôles.
