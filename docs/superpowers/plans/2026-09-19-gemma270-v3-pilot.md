# Gemma 270M V3 pilot Android integration

## Scope

Integrate the approved Gemma 3 270M V3 Q8_0 local formatter behind the
`gemma270Pilot` Gradle flag while preserving the existing Gemma4 E2B path when
the flag is false. The pilot is limited to French `Texte corrigé` requests;
the existing `Texte` cleanup path remains deterministic and model-free.

The model and licence assets are supplied by the export/CI workers. This plan
does not create, copy, or modify those assets, and it does not include Android
export, publication, or a commit.

## Approved invariants

- `BuildConfig.GEMMA270_PILOT` is true only for `-Pgemma270Pilot=true` and
  implies the existing local-format prototype build behavior.
- Pilot metadata identifies `gemma270-v3-q8-cpu`, context 8192, and a 4096
  output ceiling. The exact V3 instruction and its SHA are fixed by the
  training project; native prompt/token fixture data is consumed when supplied
  by the export worker.
- The native model is opened once per process, serialized, and released after
  completion. Installation is worker-bound, SHA/size checked, and atomic.
- Cancellation, deadline, context overflow, or a generation that does not
  reach EOS fail open to the original transcript with a diagnostic; no partial
  generated text is published.
- Protected vocabulary terms and image markers are transport/protection
  constraints. Learned corrections remain possible; the pilot does not impose
  whole-text lexical equality.
- Existing Gemma4 prompts, E2B downloader, email transforms, direct-output
  shortcuts, and timeout behavior remain unchanged outside the pilot route.

## Implementation tasks

### 1. Build variant and model store

Files: `app/build.gradle.kts`, new pilot model-store source, and the pilot
asset source-set wiring only.

- Add the opt-in build property, BuildConfig field, pilot version name/code,
  and the existing native packaging implications without changing the default
  variant.
- Add a small manifest reader/validator for the supplied model metadata.
- Install the asset to `filesDir` on a worker using staging plus atomic rename;
  verify exact size and SHA before replacing the active version and preserve a
  working version when validation fails.
- Add unit tests first for manifest validation, atomic replacement, failed
  hash/size validation, and absence of any network/downloader fallback.

### 2. Prompt and request contract

Files: new pilot prompt/request source, `LocalFormatRequest` integration, and
prompt unit tests.

- Serialize the exact V3 instruction with the native Gemma user-only template,
  `<protected_terms>`, and `<transcription>` delimiters supplied by the
  export fixture.
- Keep protected terms literal and prevent quoted terms/markers from being
  interpreted as instructions. Keep the legacy prompt serializer untouched.
- Add parity tests for the exact instruction hash, fixture prompt, token ids,
  protected terms, image markers, and greedy-generation options.

### 3. Native pilot engine and bounded generation

Files: pilot engine/facade, narrowly extended `LocalFormatNative` API if
needed, `LocalFormattingSession`, and focused JVM tests.

- Reuse the existing native bindings and resident/session serialization; do not
  duplicate the Gemma4 engine.
- Add an explicit pilot generation result/status (EOS reached, cancelled,
  deadline, context overflow) while retaining the historical `generate()` API
  behavior for Gemma4.
- Use context 8192 and a text-proportional budget capped at 4096. Keep the
  768-token value only for the prompt fixture. Avoid truncation and chunking.
- Make the pilot deadline 60 seconds and preserve the legacy 5/8/10-second
  waits outside the pilot. Ensure cancellation never waits on the UI thread,
  releases native state after completion, and cannot publish stale results.
- Add tests for output-budget calculation, EOS/partial rejection,
  cancellation, timeout, context overflow, serialization, and stale-result
  suppression before implementation.

### 4. Routing and UI

Files: `OverlayService.kt`, `LocalFormatEngine.kt`, `MainActivity.kt`, and
existing format/status test files.

- Route only French `corrected`/`Texte corrigé` requests to the pilot when the
  build flag is enabled. Keep `cleanup`/`Texte` model-free and preserve all
  historical routing when the flag is disabled.
- Keep deterministic vocabulary processing before the pilot and pass its terms
  as protected terms. Preserve manual edits, image markers, and fail-open
  behavior.
- Do not route the pilot through Gemma4 preparation/download code. Show
  “Gemma 270M V3 expérimental” and “Nettoyage français · Texte corrigé”, with
  pilot runtime/diagnostic text and no E2B/mail-specific diagnostics.
- Add routing, language/format rejection, no-shortcut, and status-label tests.

### 5. Verification

- Run focused red/green tests after each task, then the complete JVM suite with
  JDK 21, `--max-workers=2`, and a JVM heap no larger than 3 GB.
- Run the pilot assemble task once the worker assets and native prerequisites
  exist. Use the configured AVD only after the build and model export are
  available; report that no physical-device test occurred if `adb devices` is
  empty.
- Record exact commands, test counts, model manifest SHA/size, prompt SHA,
  runtime diagnostics, and any emulator limitation in the project Session Log.
